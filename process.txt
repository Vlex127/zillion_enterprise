2. AUTHORIZATION & ROLE MANAGEMENT
================================================================================

Roles are stored in the Turso database (users.role column), NOT in Clerk
metadata. The role-checking functions live in src/lib/roles.ts.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/lib/roles.ts                                                        │
│                                                                          │
│  Types:                                                                  │
│    UserRole = "admin" | "seller"                                         │
│                                                                          │
│  Functions:                                                              │
│    getUserRole(userId: string): Promise<UserRole | null>                 │
│      - Calls ensureDB() to guarantee the users table exists             │
│      - Queries: SELECT role FROM users WHERE id = ?                     │
│      - Returns role string or null if user not found                    │
│                                                                          │
│    setUserRole(userId: string, role: UserRole): Promise<void>           │
│      - Updates the role column in the users table                       │
│      - Called by changeUserRole server action (staff management)        │
│                                                                          │
│    requireRole(role: UserRole): Promise<void | Response>                │
│      - Utility for page-level role checks                               │
│      - If no userId → redirects to sign-in                              │
│      - If user's role doesn't match → redirect("/login")                │
│      - Used by server components to gate access                         │
│                                                                          │
│  Dependencies:                                                           │
│    auth() from @clerk/nextjs/server — gets current session userId       │
│    db, ensureDB from @/lib/db — database access                         │
│    redirect from next/navigation                                        │
└──────────────────────────────────────────────────────────────────────────┘

3. ROUTE PROTECTION (MIDDLEWARE)
================================================================================

Next.js middleware runs on every request before the page renders. Clerk's
clerkMiddleware() handles session validation and route protection.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/proxy.ts                                                            │
│                                                                          │
│  Imports:                                                                │
│    clerkMiddleware, createRouteMatcher from @clerk/nextjs/server         │
│                                                                          │
│  Route Matchers:                                                         │
│    Protected: /pos(.*), /daily-log(.*), /dashboard(.*), /products(.*),  │
│               /staff(.*), /analytics(.*)                                 │
│    Public:    /api/webhooks/clerk(.*), /login(.*), /signup(.*),         │
│               /sso-callback(.*)                                          │
│                                                                          │
│  Logic:                                                                  │
│    1. If route matches public matcher → skip (return early)             │
│    2. If route matches protected matcher → call auth.protect()          │
│       - If unauthenticated, Clerk automatically redirects to /login     │
│                                                                          │
│  Matcher Config:                                                         │
│    Runs on all routes EXCEPT:                                            │
│      - _next (Next.js internals)                                         │
│      - Static files (*.html, *.css, *.js, images, fonts, etc.)          │
│    Always runs on /api/* and /trpc/*                                     │
│                                                                          │
│  NOTE: Route groups (admin) and (seller) do NOT affect URL paths.       │
│  So /dashboard resolves to (admin)/dashboard/page.tsx even though the   │
│  file sits in src/app/(admin)/dashboard/page.tsx. This is Next.js       │
│  route group behavior — the parens group is invisible in the URL.       │
└──────────────────────────────────────────────────────────────────────────┘

4. USER SYNC (CLERK WEBHOOK)
================================================================================

When users sign up, update their profile, or delete their account, Clerk
fires a webhook. Zillion Enterprise receives it at /api/webhooks/clerk and
syncs the user record to the Turso database.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/app/api/webhooks/clerk/route.ts                                     │
│                                                                          │
│  Endpoint: POST /api/webhooks/clerk                                      │
│                                                                          │
│  Security:                                                               │
│    - Uses Svix to verify webhook signature                              │
│    - Extracts svix-id, svix-timestamp, svix-signature from headers      │
│    - Verifies with CLERK_WEBHOOK_SECRET env var                         │
│    - Rejects requests with missing or invalid signatures (400)          │
│                                                                          │
│  Flow:                                                                   │
│    1. Ensure CLERK_WEBHOOK_SECRET is set (500 if missing)               │
│    2. Read svix headers from request                                    │
│    3. Parse request body as JSON, then re-stringify for verification    │
│    4. Verify with wh.verify(body, headers) → WebhookEvent               │
│    5. Handle by event type:                                              │
│                                                                          │
│    Event: user.created / user.updated:                                   │
│      - Extract id, email (from email_addresses[0]), first_name,         │
│        last_name from evt.data                                           │
│      - UPSERT into users table:                                          │
│          INSERT INTO users (id, email, first_name, last_name, role)     │
│          VALUES (?, ?, ?, ?, 'seller')                                   │
│          ON CONFLICT (id) DO UPDATE SET ...                             │
│      - New users always start as 'seller' (role changed by admin)       │
│                                                                          │
│    Event: user.deleted:                                                  │
│      - DELETE FROM users WHERE id = ?                                    │
│      - Guards against missing id (returns 400)                           │
│                                                                          │
│    6. Returns 200 "Webhook processed successfully"                      │
│                                                                          │
│  Dependencies:                                                           │
│    svix — webhook signature verification                                │
│    next/headers — access request headers                                │
│    @/lib/db (ensureDB, db) — database operations                       │
└──────────────────────────────────────────────────────────────────────────┘

CLERK DASHBOARD SETUP
  - Create an endpoint at: https://your-domain/api/webhooks/clerk
  - Subscribe to events: user.created, user.updated, user.deleted
  - Copy the Signing Secret (whsec_...) into .env as CLERK_WEBHOOK_SECRET
  - The middleware (src/proxy.ts) explicitly allows this route as public

5. DATABASE SCHEMA & MIGRATION
================================================================================

Using Turso (edge-hosted libSQL, SQLite-compatible). The client is configured
with DATABASE_URL and DATABASE_TOKEN from environment.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/lib/db.ts                                                           │
│                                                                          │
│  Connection:                                                             │
│    createClient({ url, authToken }) → db                                 │
│    - url: libsql://host.turso.io (edge HTTP protocol)                   │
│    - authToken: JWT-based authentication token                           │
│                                                                          │
│  ensureDB(): Lazy singleton migration runner                             │
│    - Runs once (per process lifetime) on first call                     │
│    - Uses initPromise pattern: if already running, returns same promise  │
│    - On error: resets initPromise to null for automatic retry           │
│    - All DB queries in the app call await ensureDB() before executing   │
│                                                                          │
│  Tables created by ensureDB():                                           │
│                                                                          │
│  1. users                                                                 │
│     id         TEXT PRIMARY KEY (Clerk user ID)                          │
│     email      TEXT NOT NULL                                              │
│     first_name TEXT                                                       │
│     last_name  TEXT                                                       │
│     role       TEXT NOT NULL DEFAULT 'seller'                             │
│     created_at TEXT NOT NULL DEFAULT datetime('now')                      │
│                                                                          │
│  2. products                                                              │
│     id            TEXT PRIMARY KEY DEFAULT lower(hex(randomblob(16)))     │
│     name          TEXT NOT NULL                                            │
│     brand         TEXT                                                     │
│     category      TEXT                                                     │
│     inventoryType TEXT NOT NULL DEFAULT 'BULK'                             │
│                   CHECK (inventoryType IN ('SERIALIZED', 'BULK'))         │
│     cost_price    REAL NOT NULL                                            │
│     retail_price  REAL NOT NULL                                            │
│     bulk_stock    INTEGER NOT NULL DEFAULT 0                               │
│     created_at    TEXT NOT NULL DEFAULT datetime('now')                    │
│     updated_at    TEXT NOT NULL DEFAULT datetime('now')                    │
│                                                                          │
│  3. sales                                                                  │
│     id             TEXT PRIMARY KEY DEFAULT lower(hex(randomblob(16)))    │
│     product_id     TEXT NOT NULL → products(id)                           │
│     seller_id      TEXT NOT NULL → users(id)                              │
│     quantity       INTEGER NOT NULL                                        │
│     unit_price     REAL NOT NULL                                           │
│     total          REAL NOT NULL                                           │
│     cost_price     REAL NOT NULL                                           │
│     profit         REAL NOT NULL                                           │
│     payment_method TEXT NOT NULL CHECK (... IN ('cash','transfer','pos')) │
│     created_at     TEXT NOT NULL DEFAULT datetime('now')                   │
│                                                                          │
│  4. product_items                                                         │
│     id         TEXT PRIMARY KEY DEFAULT lower(hex(randomblob(16)))        │
│     product_id TEXT NOT NULL → products(id)                               │
│     imei       TEXT UNIQUE                                                 │
│     status     TEXT NOT NULL DEFAULT 'in_stock'                           │
│                CHECK (status IN ('in_stock', 'sold'))                     │
│     sale_id    TEXT → sales(id)                                            │
│     created_at TEXT NOT NULL DEFAULT datetime('now')                       │
│                                                                          │
│  Migration (backward-compat):                                             │
│    - Checks if products table has inventoryType column                   │
│    - If missing: ALTER TABLE products ADD COLUMN inventoryType TEXT       │
│      DEFAULT 'BULK' (without CHECK — SQLite doesn't support CHECK in     │
│      ALTER TABLE ADD COLUMN)                                              │
│                                                                          │
│  SETUP SCRIPT:                                                            │
│    scripts/setup-db.mjs — standalone Node.js script that creates the     │
│    users table manually (same DDL as ensureDB). Run with:                │
│      node scripts/setup-db.mjs                                           │
│    Requires dotenv to load .env file.                                    │
└──────────────────────────────────────────────────────────────────────────┘

6. ROOT REDIRECT LOGIC
================================================================================

The homepage (/) determines where to send users based on authentication and
role.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/app/page.tsx                                                        │
│                                                                          │
│  Flow:                                                                   │
│    1. Call auth() from @clerk/nextjs/server → get userId                │
│    2. If no userId → redirect("/login")                                 │
│    3. Call getUserRole(userId) from @/lib/roles                         │
│       - This queries the Turso users table                              │
│       - Calls ensureDB() internally                                      │
│    4. If role === "admin" → redirect("/dashboard")                      │
│    5. If role === "seller" → redirect("/pos")                           │
│    6. Otherwise (no role found) → redirect("/login")                    │
│                                                                          │
│  NOTE: This is a server component (async, no "use client").              │
│  Uses force-dynamic behavior implicitly because it reads auth state.     │
└──────────────────────────────────────────────────────────────────────────┘

effect on URLs — paths are /dashboard, /products, /staff, /analytics.

Middleware protects these routes. Only users with role='admin' should access
them (enforced by page-level checks via requireRole()).

9. SERVER ACTIONS
================================================================================

Server actions handle mutations — they run on the server but can be called
directly from client components via form actions.

┌──────────────────────────────────────────────────────────────────────────┐
│  src/lib/actions.ts                                                      │
│                                                                          │
│  All functions use "use server" directive.                               │
│                                                                          │
│  addProduct(formData: FormData): Promise<void>                           │
│    - Reads inventoryType, name, brand, category, prices                 │
│    - If SERIALIZED: splits IMEI textarea by newlines into array          │
│    - If BULK: reads bulk_stock                                           │
│    - Calls createProduct() from queries                                  │
│    - Revalidates /products and /dashboard                                │
│                                                                          │
│  editProduct(id: string, formData: FormData): Promise<void>              │
│    - Reads optional fields from form (only submits non-empty)           │
│    - If SERIALIZED: appends new IMEIs (does not touch existing)          │
│    - Calls updateProduct() from queries                                  │
│    - Revalidates /products and /dashboard                                │
│                                                                          │
│  recordSale(formData: FormData): Promise<void>                           │
│    - Gets userId from Clerk auth()                                       │
│    - Reads product_id, quantity, prices, payment_method                 │
│    - Calculates total = qty × unit_price, profit = qty × margin         │
│    - If serialized: passes item_ids from IMEI lookup result              │
│    - Calls createSale() from queries                                     │
│    - Revalidates /pos, /daily-log, /dashboard, /products, /analytics     │
│                                                                          │
│  changeUserRole(userId: string, role: "admin" | "seller"): Promise<void> │
│    - Calls setUserRole() from roles                                      │
│    - Revalidates /staff                                                  │
│                                                                          │
│  Dependencies:                                                           │
│    @/lib/queries (createProduct, updateProduct, createSale)              │
│    @/lib/roles (setUserRole)                                             │
│    @clerk/nextjs/server (auth)                                           │
│    next/cache (revalidatePath)                                           │
└──────────────────────────────────────────────────────────────────────────┘

JavaScript (e.g., IMEI validation as the user types).

┌──────────────────────────────────────────────────────────────────────────┐

│                                                                          │
│  Returns all ProductItem records for a product:                          │
│    [{ id, product_id, imei, status, sale_id, created_at }, ...]         │

│  GET /api/products/{productId}/lookup-imei?imei=XXXXXXXX                 │
│  src/app/api/products/[productId]/lookup-imei/route.ts                  │
│                                                                          │
│  Validates a single IMEI against the database:                           │
│    Query: SELECT id, status FROM product_items WHERE product_id=?       │
│           AND imei=?                                                     │
│    Response: { found: boolean, id?: string, status?: string }            │

│                                                                          │
│  Dependencies:                                                           │
